## 二、F18 手绘底图——这一轮挖出来的事

### 调研结论

反编译 `3dmap-10.0.600.jar` 拿到样式解析器（`com/amap/api/col/3l/cz.class`，原类名 `StyleParser.java`）。解析器支持的**完整 styler 词表**：

- 颜色：`color` / `fillColor` / `strokeColor` / `textFillColor` / `textStrokeColor`
- 透明：`opacity` / `fillOpacity` / `strokeOpacity` / `textFillOpacity` / `textStrokeOpacity`
- 几何：`lineWidth`
- 显示：`visible`、`showIcon`、`showLabel`
- 贴图替换：`textureId`、`textureName`（高德控制台加密样式包路线）

可用 `featureType` 内部名（cy.class）：`aois / arterial / borders / boundary / building / buildings / business / city / continent / country / culture / district / districtlable(SIC) / edu / foreign / green / guideBoards / health / highSpeedRailway / highWay / highway / labels / land / levelFourRoad / levelThreeRoad / local / nationalRoad / other / overPass / parkingLot / poilabel / pois / province / provincial / provincialRoad / public / railway / regions / ringRoad / roads / roadsBeingBuilt / scenicSpot / secondaryRoad / sports / subway / subwayBeingBuilt / subwayline / town / traffic / underPass / village / water`。未知类型被静默忽略，可双写词表无害。

### 真机实战（金丝雀法）**踩到的坑**

1. **`setStyleData(byte[])` 在 3dmap 10.0.600 上不生效**。水色金丝雀变红→屏幕水仍蓝。
2. **`setStyleDataPath(String)` 也不生效**。文件路径确认写到 filesDir 并加载，APK 内的字节和设备上的文件都被验证过，屏幕水仍蓝。
3. **裸数组格式（无 `styleJson` 包裹）也不生效**。试过两套词表格式。
4. **高德加密样式包（控制台下载）是唯一正规路线**：必须登录 [lbs.amap.com 控制台](https://console.amap.com) → 个性化地图 → 编辑并下载 **不带样式 ID 的离线样式包** → 把 `style.data / style_extra.data / textures.data` 三个文件放进 `app/src/main/assets/mapstyle/console/`。

### 落地实现（已推送 commit `c5d00a6` + 最新提交）

- `MapHomeScreen.kt` 的 `setCustomMapStyle` 启动逻辑：优先尝试 `assets/mapstyle/console/`，命中就把三个文件覆盖到 `filesDir/console_style/` 并通过 `setStyleDataPath / setStyleExtraPath / setStyleTexturePath` 挂载；未命中回退到 assets 里的手写 JSON。
- 叠加层 `HandDrawn.kt::mapPaperOverlayBitmap(w, h)`：整屏预烘焙一次（暖纸色低透明 15% + 暗/亮纤维点 + 抄纸纹细线），source-over 一把画完。实测 `BlendMode.Multiply` 在该设备渲染管线里退化为 source-over，所以**不再依赖 Multiply**，把"要做的事"直接烘焙到位图里。
- 性能：原先每帧几百次瓦片 drawImage → 现在每帧一次 drawImage。地图滑动更顺。
- 视觉效果：诚实地说，目前只是把默认高德地图向纸色调低 15% 偏移并加了纤维点，**真正的"全要素手绘风"需要控制台加密样式包到位后才能到位**。

## 三、CI 从未绿过——四层根因

仓库从建仓起到 `5160722` 的所有 push，GitHub Actions 全部 failure（`Unit tests` 步骤）。一次调试发现是四层叠加的根因：

1. **`gradlew` 缺可执行位**（`100644` in git）。Windows 提交时丢失 `+x`，Linux CI 第一次执行 `./gradlew` 立即 exit 126。**修：commit 时用 `git update-index --chmod=+x gradlew` 再提交（`a5bb0cc`）**。
2. **wrapper 指向腾讯云镜像**（`mirrors.cloud.tencent.com/gradle/...`）。GitHub runner 在境外拉不到，14 秒即败。**修：CI 步骤前置 `sed -i 's#mirrors.cloud.tencent.com/gradle#services.gradle.org/distributions#' gradle/wrapper/gradle-wrapper.properties`（`394f3d2`）**。注意域名之外还要补 `/distributions` 路径段，官方地址是 `services.gradle.org/distributions/gradle-x.y.z-bin.zip`（`2d01579`）。
3. **阿里云 maven 镜像在 GitHub runner 上不稳**。KSP 插件解析 5 个仓库全失败。**修：`settings.gradle.kts` 用 `System.getenv("CI") == "true"` 跳国内镜像（`3f7f757`）**。注意 `pluginManagement {}` 块早期求值读不到顶层 `val`，变量要在块内各自声明（`bab5251`）。
4. **构建目录被重定向到 `D:/smellmap-build`**（中文路径上的兼容方案），但 CI 上是个相对怪目录，`app/build/outputs/...` 路径恒不存在 → artifact 永远上传空。**修：CI 加 `env: TASTEMAP_BUILD_ROOT: ${{ github.workspace }}/build`（`0cb65a0`）**，artifact 路径同步改到 `build/app/outputs/...`。

诊断手段：工作流失败步骤用 `::error title=...` 把日志尾发到 check-runs 注解（匿名 API 可读），不用登录也能看到失败原因。

**结果（`bab5251`）：Unit tests 165s + assembleDebug 105s + 48MB APK artifact 全部通过。**

## 五、缓存清理建议

| 阶段 | 清理对象 | 影响 |
|---|---|---|
| **任何时候** | `D:\smellmap-build` | **零影响**。Gradle 增量构建会重生成（首次 8 分钟，再次 30-60 秒）。 |
| **CI 跑新版本前** | `D:\gradle-home\caches\transforms\*` | 零影响。transforms 会在下次构建时重做。 |
| **换机器 / 改 SDK 版本前** | `D:\gradle-home` | **中等影响**。下次冷构 8 分钟（首次下依赖），随后恢复 1.8GB 缓存约 3 分钟。 |
| **绝不动** | `D:\android-sdk`、`D:\jdk-17` | 缺则构建直接挂。 |
| **真机调试切换风格前** | `run-as com.tastemap.app rm files/handdrawn_style.json` 然后重启 app | 零影响。但**仅在怀疑 SDK 缓存了样式时**才清。 |
